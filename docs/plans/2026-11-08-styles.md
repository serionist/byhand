# Write in the user's own style, and learn their styles

## Goal

The plugin writes: a request to draft a mail, a message, a post or a document starts `write`, which writes in the
user's style and without the signs, and reads its own draft against them before showing it. `learn` turns the user's
own samples into a style, never from text that reads as AI-written, and lists styles and sets their defaults. The
bootstrap plan's Step 6 (#6), as its decisions changed it (no command on a user's machine, 2026-11-07; fewer tokens,
2026-11-08) and the maintainer's calls on #6 (2026-11-08).

In scope: the style format and its index, the `write` and `learn` skills, eval graders and tries by hand.
Out of scope: a project's styles (`.byhand/styles/` stays reserved; the maintainer's call, Fit I7), `keeps` in
`check`, decks and sheets (0.4.0; a deck's text is written as a document until then), learning from edits (0.5.0),
the trigger measurements and the maintainer's own style (Step 7).

## Design

### Styles and their index

A user's styles live in `~/.byhand/styles/` (AGENTS.md, one-way doors). Read and Write take `~/` as written (tried in a
headless session, Claude Code 2.1.319, Windows), so neither skill needs the home folder's path.

The folder holds `index.md` (the maintainer's call on #6: the main session can't list a folder on macOS, Linux and
WSL) and one `<name>.md` per style:

```markdown
# byhand styles

| Style | Language | Default for |
|---|---|---|
| work-mail | en | email, message |
| csalad | hu | message |
```

A style:

```markdown
---
register: plain, warm, direct
keeps: [any-bold-lead-in-list]
---

# work-mail

How this person writes, in prose and bullets: sentence length, openings and sign-offs, register, punctuation habits,
what they never write.

## Corrections

- 2026-11-08, email: never sign off with "Best regards"; "Thanks," and the first name.

## Excerpts

3 to 5 short passages from the samples, the user's own.
```

- **The index is the one place for a style's name, language and defaults;** the style holds what the model writes by.
  The bootstrap plan put `name`, `kinds`, `language`, `default_for` and `updated` in the frontmatter: with an index
  they would be said twice and drift, and nothing reads `kinds` or `updated` (Fit I1, I8). A style's language still
  shows in its excerpts when it is read alone.
- **One default per kind and language:** setting a default clears it from the style that held it. An index edited by
  hand with two rows claiming one: the first row wins.
- **The index is the list:** a style file it doesn't name is never used, as `plugin/README.md` says.
- **`keeps`:** sign ids the user's own samples use on purpose and chose to keep; `write` leaves them in for a draft in
  that style. `check` stays as merged in 0.1.0: it can't tell a text is in a style without asking (Fit I6).
- **`## Corrections`** beats the rules, and both beat the signs. "Remember: …" adds one, through `learn`.
- **Size:** a style stays under 4 KB (the bootstrap plan's decision of 2026-11-08); `learn` holds it when it saves.
- **Readers keep what they don't know:** a frontmatter key, a section or an index column a later release adds.

### The `write` skill

`plugin/skills/write/SKILL.md`, `allowed-tools: Read`. It starts on a request to write, draft, reply to or rewrite a
message, a mail, a post or a document, in any language; never on code-adjacent writing (a commit message, a README, a
docstring, a PR description, a code comment). It asks nothing it can judge itself:

1. **The kind:** `message`, `email`, `post` or `document`.
2. **The language:** the one the user names; else that of the text replied to; else the request's.
3. **The model:** its own family and version, from its model id in the system prompt (`claude-opus-5-5` is claude
   5.5). An id it can't read: the `any` files alone.
4. **The style:** Read `~/.byhand/styles/index.md`. A style the user names; else the default for the kind and
   language; else the one style in that language that is the default for no kind, if there is one (the maintainer's
   call, Round 1, Q1: a family-chat style never writes a client's mail); else, with several such, ask; with none, or
   no index, the signs alone and nothing said (the maintainer's call on #6). A style the index names but that isn't
   there is skipped, and said.
5. **Read the signs,** only those not in context since the last compaction: the short files, `any/any`, `any/<family>`,
   `<language>/any`, `<language>/<family>` (and a script variant's base language's), and for a post or a document the
   long ones too, under `${CLAUDE_PLUGIN_ROOT}/signs/`. A file that isn't there has no signs: go on. Then the style.
6. **Draft,** by the style first (its corrections above its rules), then the signs: no strong or usual sign; never 3
   different weak ones in a paragraph; a sign for the model's family only where its range holds the model's version;
   none the style keeps.
7. **Read the draft against the signs and the style,** and rewrite what it finds (the maintainer's call on #6: no
   file, no scan).
8. **Answer with the draft,** and nothing the user didn't ask for: no preamble, no list of what was avoided.

A second draft in the same language and model reads nothing new. Claude Code's skill grant lasts the turn it starts
in, so `write` starts again for each draft; the user allows the Skill tool once.

### The `learn` skill

`plugin/skills/learn/SKILL.md`, `allowed-tools: Read`, with the style format in it (Fit I5). It starts on a request to
learn a style, list styles, set or clear a default, remove a style, or remember a correction:

- **Learn:** take the samples, files the user points at or text they paste (the maintainer's call on #6). Screen each
  by `check`'s own steps, read from `${CLAUDE_PLUGIN_ROOT}/skills/check/SKILL.md` (Fit I4); a file Read returns keeps
  its `${CLAUDE_PLUGIN_ROOT}` unsubstituted, so `learn` names what it stands for, the plugin's folder, in its own text.
  A file goes through `scan`, pasted text is read. A sample with a strong or usual sign, or a weak cluster, is left out and named, unless the
  user says it is theirs. Judge the language and propose a name from the samples (Fit I2). Write the style from what
  remains: how the person writes, in their own patterns, and which signs their samples use on purpose. Show it with
  one question: the name, the kinds it is the default for (naming a style that would lose that default), and the
  signs to keep. Save on a yes: the style, and its row in the index. A name the index already has is said, and the
  old style's `## Corrections` carry over into the new one.
- **List:** the index.
- **Default, remove:** edit the index. A removed style's file is named for the user to delete, as no tool here
  deletes; to rename, the user learns it again or renames the file by hand (Fit I9).
- **Remember:** a correction the user gives ("remember: …") goes under the `## Corrections` of the style the last
  draft used, else of the one the user names, asked when unclear; dated, with the kind it came from.

Every save asks the user (Write is not pre-approved), as a save should.

### Alternatives

- **A lookup agent with Glob:** an agent start on every draft. The maintainer chose the index.
- **Defaults in each style's frontmatter only:** needs a listing, which is a command on macOS and Linux.
- **`write` saving its draft and running `scan`:** a Write prompt on every draft. The maintainer chose its own read.
- **A project's styles now:** a second index read on every draft, a precedence rule and a `.gitignore` prompt, for
  what is a user style tied to a folder; reserved for later (Fit I7).
- **A `styles` skill, or a package parser for styles:** cut on 2026-11-07; the skills read Markdown.

## Compatibility

- **One-way doors:** the style format and its index, agreed by the maintainer on #6 (comments of 2026-11-08); the
  skills' names `write` and `learn`, already among the three. `.byhand/styles/` stays a reserved place, unused in
  0.1.0.
- No change to the catalogue, a sign's id or a rendered file.

## Steps

1. **`write`,** `plugin/skills/write/SKILL.md`, listed in `plugin/README.md`. The gate's plugin skill check proves its
   form. A test in `tests/test_render.py` holds that every `${CLAUDE_PLUGIN_ROOT}/signs/` path a plugin skill or agent
   names ends with a suffix `render` writes (Fit I10): the names changed twice already.
2. **`learn`,** `plugin/skills/learn/SKILL.md`, with the format. The same checks.
3. **Evals and tries.** Eval graders on pasted text, as Step 5 found the harness gives a case no file (Fit I3): the
   existing `no-check-on-writing` case also grades `write` starting; the four `check-*` cases grade `write` not
   starting; a new hu case asks for a Hungarian mail, graded on `write` starting and its draft holding none of three
   strong patterns from `any/check.md` (`regex`, `match: not_contains`: the preamble, the self-reference, the chat
   tool's markup); a new case asks `learn` to learn a style from pasted samples, one of them AI-written, graded on
   `learn` starting, `write` not starting, and its answer leaving that one out (an `llm` grader; no save, as Write
   isn't granted); a "remember: …" case graded on `learn` starting, as Claude Code's own memory might take it. By hand, in
   a headless session with a throwaway `~/.byhand/` that the try removes after, and stops if one already exists: a default per kind and language (a
   Hungarian and an English default for `message`), a kept sign left in, a correction above a rule, a style the index
   names that is missing, `learn` saving a style and its index row.
4. **finish-work:** `uv run tools/gate.py full`, `review-code` until clean, the PR, which names the Claude Code
   version, the models and what ran by hand.

## Tests

- Unit (CI): the gate's plugin checks for both skills; the path test in Step 1. No package code changes.
- By hand: the eval cases, three runs each; the headless tries in Step 3, on Windows; one try on macOS, Linux or WSL if
  one is at hand, else said in the PR.
- What none can show: whether a draft reads as the user's. Step 7's maintainer read is the only test of that.

## Risks

| Risk | Answer |
|---|---|
| The model misreads its own id, or an id it doesn't know | `any` files alone; Step 7 runs an id the catalogue has never seen |
| The index and the style files drift (a style edited or deleted by hand) | the index is the one place for name, language and defaults; a style it names that isn't there is skipped and said |
| A crowded skill listing drops `write`'s description | Step 7 measures; the `SessionStart` hook is the fallback (bootstrap plan, Q4) |
| A sample is AI-written and the user says it's theirs | their call: `learn` names the signs it found and keeps the sample |
| Reading `~/.byhand/` on macOS and Linux | not tried there; Read with `~` worked on Windows |
