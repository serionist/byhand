# Write in the user's own style, and learn their styles

## Goal

The plugin writes: a request to draft a mail, a message, a post or a document starts `write`, which writes in the
user's style and without the signs, and reads its own draft against them before showing it. `learn` turns the user's
own samples into a style, never from text that reads as AI-written, and lists styles and sets their defaults. The
bootstrap plan's Step 6 (#6), as its decisions changed it (no command on a user's machine, 2026-11-07; fewer tokens,
2026-11-08) and the maintainer's calls on #6 (2026-11-08).

In scope: the style format and its index, the `write` and `learn` skills, a few eval cases and tries by hand.
Out of scope: decks and sheets (0.4.0; a deck's text is written as a document until then), learning from edits
(0.5.0), the trigger measurements and the maintainer's own style (Step 7).

## Design

### Styles and their index

Where they live is fixed (AGENTS.md, one-way doors): `~/.byhand/styles/` for the user's, `.byhand/styles/` in a
project's working directory for the project's. Read and Write take `~/` as written (tried in a headless session,
Claude Code 2.1.319, Windows), so neither skill needs the home folder's path.

Each folder holds `index.md` (the maintainer's call on #6: the main session can't list a folder on macOS, Linux and
WSL) and one `<name>.md` per style:

```markdown
# byhand styles

| Style | Language | Kinds | Default for |
|---|---|---|---|
| work-mail | en | email, message | email, message |
| csalad | hu | message | message |
```

A style:

```markdown
---
name: work-mail
register: plain, warm, direct
keeps: [any-bold-lead-in-list]
updated: 2026-11-08
---

# work-mail

How this person writes, in prose and bullets: sentence length, openings and sign-offs, register, punctuation habits,
what they never write.

## Corrections

- 2026-11-08, email: never sign off with "Best regards"; "Thanks," and the first name.

## Excerpts

3 to 5 short passages from the samples, the user's own.
```

- **The index is the one place for a style's language, kinds and defaults;** the style holds what the model writes
  by. The bootstrap plan put `kinds`, `language` and `default_for` in the frontmatter: with an index they would be
  said twice and drift, so they move to the index, before `0.1.0` fixes the format.
- **`keeps`:** sign ids the user's own samples use on purpose and chose to keep; `write` and `check` skip them for a
  text in that style.
- **`## Corrections`** beats the rules, and both beat the signs. "Remember: …" adds one, through `learn`.
- **Size:** a style stays under 4 KB (the bootstrap plan's decision of 2026-11-08); `learn` holds it when it saves.
- **Readers keep what they don't know:** a frontmatter key, a section or an index column a later release adds.
- **A project's style** of the same name wins over the user's, and the project's default for a kind and language wins.
  `learn` adds `.byhand/` to the project's `.gitignore` when it first saves there, and says so; this repo's gate
  refuses a tracked `.byhand/` file.

### The `write` skill

`plugin/skills/write/SKILL.md`, `allowed-tools: Read`. It starts on a request to write, draft, reply to or rewrite a
message, a mail, a post or a document, in any language; never on code-adjacent writing (a commit message, a README, a
docstring, a PR description, a code comment). It asks nothing it can judge itself:

1. **The kind:** `message`, `email`, `post` or `document`.
2. **The language:** the one the user names; else that of the text replied to; else the request's.
3. **The model:** its own family and version, from its model id in the system prompt (`claude-opus-5-5` is claude
   5.5). An id it can't read: the `any` files alone.
4. **The style:** one the user names; else the project's default for the kind and language, then the user's (Read
   `.byhand/styles/index.md`, then `~/.byhand/styles/index.md`); else, with several in that language, ask; with none,
   the signs alone, and nothing said (the maintainer's call on #6).
5. **Read the signs,** only those not in context since the last compaction: the short files, `any/any`, `any/<family>`,
   `<language>/any`, `<language>/<family>` (and a script variant's base language's), and for a post or a document the
   long ones too, under `${CLAUDE_PLUGIN_ROOT}/signs/`. A file that isn't there has no signs: go on. Then the style.
6. **Draft,** by the style first (its corrections above its rules), then the signs: no strong or usual sign; never 3
   different weak ones in a paragraph; a sign for the model's family only where its range holds the model's version;
   none the style keeps.
7. **Read the draft against the signs and the style,** and rewrite what it finds (the maintainer's call on #6: no
   file, no scan).
8. **Answer with the draft,** and nothing the user didn't ask for: no preamble, no list of what was avoided.

A second draft in the same language and model reads nothing new. Claude Code's skill grant lasts the turn it starts
in, so `write` starts again for each draft; the user allows the Skill tool once.

### The `learn` skill

`plugin/skills/learn/SKILL.md`, `allowed-tools: Read`, with the style format beside it, `plugin/skills/learn/format.md`,
which it reads when it saves. It starts on a request to learn, list, change or remove a style, set or clear a default,
or remember a correction:

- **Learn:** ask the name, the language, the kinds, and the kinds it is the default for; take samples, files the user
  points at or text they paste (the maintainer's call on #6). Screen each as `check` does: a file through `scan`,
  pasted text by reading. A sample with a strong or usual sign, or a weak cluster, is left out and named, unless the
  user says it is theirs. Then write the style from what remains: how the person writes, in their own patterns, and
  which signs their samples use on purpose (asked: keep?). Show it; save on a yes, the style and its row in the index.
- **List:** both indexes, the project's first.
- **Default, rename, remove:** edit the index; a removed style's file is named for the user to delete, as no tool here
  deletes.
- **Remember:** a correction the user gives ("remember: …") goes under the style's `## Corrections`, dated, with the
  kind it came from.

Every save asks the user (Write is not pre-approved), as a save should.

### Alternatives

- **A lookup agent with Glob:** an agent start on every draft. The maintainer chose the index.
- **Defaults in each style's frontmatter only:** needs a listing, which is a command on macOS and Linux.
- **`write` saving its draft and running `scan`:** a Write prompt on every draft. The maintainer chose its own read.
- **A `styles` skill:** cut on 2026-11-07; `learn` lists and sets defaults.
- **A package parser for styles:** no command on a user's machine; the skills read Markdown.

## Compatibility

- **One-way doors:** the style format and its index, agreed by the maintainer on #6 (comment of 2026-11-08); the
  skills' names `write` and `learn`, already among the three.
- No change to the catalogue, a sign's id or a rendered file.

## Steps

1. **`write`,** `plugin/skills/write/SKILL.md`, listed in `plugin/README.md`. The gate's plugin skill check proves its
   form.
2. **`learn` and the format,** `plugin/skills/learn/SKILL.md` and `format.md`. The same check, and its link check.
3. **Evals and tries.** Eval cases, pasted text, as Step 5 found the harness gives a case no file: `write` starts on a
   mail request in en and hu and its draft holds no strong sign (a regex grader on the preamble and self-reference);
   `write` doesn't start on a commit message (`min: 0, max: 0`); `learn` starts on "learn my style from these" with
   pasted samples, one of them AI-written, and its answer leaves that one out (an `llm` grader). The styles by hand,
   in a headless session in a scratch project: a project style over a user's of the same name, a default per kind and
   language (a Hungarian and an English default for `message`), a kept sign left in, `.gitignore` written on the first
   project save. The user-level style is tried with a throwaway `~/.byhand/` that the try removes after.
4. **finish-work:** `uv run tools/gate.py full`, `review-code` until clean, the PR, which names the Claude Code
   version, the models and what ran by hand.

## Tests

- Unit (CI): the gate's plugin checks for both skills and `format.md`. No package code changes.
- By hand: the eval cases, three runs each; the headless tries in Step 3, on Windows; one try on macOS, Linux or WSL if
  one is at hand, else said in the PR.
- What none can show: whether a draft reads as the user's. Step 7's maintainer read is the only test of that.

## Risks

| Risk | Answer |
|---|---|
| The model misreads its own id, or an id it doesn't know | `any` files alone; Step 7 runs an id the catalogue has never seen |
| The index and the style files drift (a style edited or deleted by hand) | the index is the one place for language, kinds and defaults; a style it names that isn't there is skipped and said |
| A crowded skill listing drops `write`'s description | Step 7 measures; the `SessionStart` hook is the fallback (bootstrap plan, Q4) |
| A sample is AI-written and the user says it's theirs | their call: `learn` names the signs it found and keeps the sample |
| Reading `~/.byhand/` on macOS and Linux | not tried there; Read with `~` worked on Windows |
