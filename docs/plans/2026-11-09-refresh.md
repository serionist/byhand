# Check the catalogue's sources on a schedule and open an issue when one changes

## Goal

A source the catalogue cites changes, and a maintainer hears of it within its `due` (a day for a daily source, a week
for a weekly one): an issue names the source, the
revision the signs were written from and the one now live, with a link to the change, so they run `propose-signs` on
it. No model, no key, and no fetched text in the issue (AGENTS.md, The refresh and Traps; the bootstrap plan's design,
0.2.0). The maintainer's first ask: signs from many sources, refreshed "daily or something".

In scope: `byhand refresh`, a scheduled workflow, tests with no network, a run against the live sources by hand.
Out of scope: drafting the signs (`propose-signs`, by a maintainer; #30 is the agent that may do it later), releasing
on a sign change (#31), finding new sources (#32).

## Design

### `byhand refresh`

The repo's own tool (never a user's), standard library only (`urllib`, `json`). For each source whose `due` has come
round since its `read_at` date (daily 1 day, weekly 7, monthly 30, quarterly 90; `by-hand` never), it reads the current
revision by its `feed`:

| Feed | Read | Changed when |
|---|---|---|
| `mediawiki` | the page's latest revision id, from the site's `api.php` (`prop=revisions`, `rvprop=ids`, `redirects=1`, so a moved page is followed) | the id differs from `read_at.revision`; a missing page is unreadable |
| `github` | `GET /repos/{repo}/compare/{read_at.commit}...HEAD`, the files it changed | a changed file's `filename` or `previous_filename` (a rename) sits under one of `paths`, by whole path segments (`evals` doesn't match `evals2/`), or the list is cut at GitHub's 300 files |
| `hf` | `GET https://huggingface.co/api/datasets/{dataset}`, its `sha` | the sha doesn't start with `read_at.commit` |
| `none` | nothing: a person reads it | never |

Any other feed (`arxiv`, which no source uses yet) has no reader and counts as unreadable (Fit I4), so the first source
that takes one fails loudly instead of never changing.

It prints one line per source checked and writes, for each changed one, `<out>/<id>.md`: the issue's body, made only of
ids, dates, which of our own `paths` matched and links (a MediaWiki diff, a GitHub compare, the dataset's commits), never a
page's text, a commit message or a file name from the source (R1 P2). A source it can't read (a network error, an unknown commit, a missing page) is reported and
doesn't stop the run; after the files are written, the run exits 1 if any source with a feed couldn't be read (Fit
I3), so a scheduled run fails and GitHub mails the maintainer. The generic User-Agent `byhand-catalogue/0.0
(https://github.com/serionist/byhand)` on every request; the GitHub token from the environment, sent to
`api.github.com` only.

### The workflow

`.github/workflows/refresh.yml`: daily on a schedule off the hour, and by hand (`workflow_dispatch`), one run at a time
(`concurrency`), `permissions: contents: read, issues: write`, actions pinned by commit as `ci.yml` pins them. It runs
`uv run byhand refresh --out refresh/`, then, even when that step failed (`if: ${{ !cancelled() }}`), lists the open
issues labelled `refresh` once (`gh issue list --label refresh --state open --limit 1000 --json title`, past the
default 30; R1 P1), and for each file opens an issue titled `Refresh: <id> changed` with the `refresh`
label, unless a title matches exactly (`grep -Fx`, never a search, which matches words and lags; Fit I1, I2). The
label is created once if it's missing; no milestone, as these issues are upkeep, and a closed milestone would fail
the step. The issue says to run `propose-signs` on the source, and that its PR carries `Closes #<this issue>`;
`propose-signs` moves `read_at` when it is done, even when the change gave no sign. Closing the issue by hand without
moving `read_at` brings it back on the next run (Fit I5).

### Alternatives

- **Weekly, all sources:** simpler cron, but `due` says how often a person should re-read each source, counted from
  its `read_at` date; a daily run with `due` honours it and the maintainer's "daily", for one date subtraction.
- **Diffing page text:** the change a person reads is one link away; fetched text in an issue is what the Traps rule
  out.
- **A model drafting the change in CI:** a key and unattended fetched text; that is #30's question.
- **Per-path GitHub commits (`commits?path=`):** one call per path; `compare` is one call per repo.

## Compatibility

None: the schema already holds `feed`, `due` and `read_at`. No one-way door.

## Steps

1. **`byhand refresh`,** `src/byhand/refresh.py` and its subcommand in `cli.py`. `tests/test_refresh.py` with the
   network replaced: each feed changed and unchanged, `due` not yet come round, a moved and a missing page, a non-ASCII
   page title (R1 I6), a renamed file and a path that only shares a prefix (R1 P3), a cut file list, a source that can't be read, a feed with no reader, the token sent to GitHub only, the issue body holding no
   fetched text, the exit codes.
2. **The workflow,** `.github/workflows/refresh.yml`, listed in `AGENTS.md`'s `.github/` row.
3. **A live run by hand:** `uv run byhand refresh --out .local/refresh/` against today's sources, its output in the PR.
4. **finish-work:** the gate, `review-code` until clean, the PR.

## Tests

- Unit (CI): `tests/test_refresh.py`, no network; the gate.
- By hand: the live run in Step 3; the workflow once by `workflow_dispatch` after the merge, said in the PR as not
  yet run.
- What none can show: whether a change matters, which `propose-signs` and its reviewer judge.

## Docs

`docs/USAGE.md` (`byhand refresh`), `AGENTS.md` (the workflow, the command, and "Hosted CI never … reads the live
sources" narrowed to CI's tests, as `refresh.yml` reads them; `ci.yml`'s header the same; R1 P4), `CHANGELOG.md` (not a user's change: no
line), `.claude/skills/propose-signs/SKILL.md` (starting from a refresh issue, its PR closing it).

## Risks

| Risk | Answer |
|---|---|
| GitHub's API rate limit without a token | the workflow passes `GITHUB_TOKEN`; by hand, unauthenticated, 14 repos fit 60 calls an hour |
| A force-pushed repo loses the `read_at` commit | `compare` fails; the source is reported as unreadable, not as unchanged |
| An issue a day for a busy source | one open issue per source: the next run skips it until it closes |
| A fetched value carrying instructions | the issue holds ids, dates, paths and links only |
